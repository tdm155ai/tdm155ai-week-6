title: Tacit knowledge and skill files
description: What can be written into a skill and what cannot; the limit of instructions.

Write "check continuity" into a skill file and the model will check continuity, for some meaning of the word. It will not know which continuity error matters in this scene: that the glass moved between shots is nothing, that her expression reset is everything. Michael Polanyi's phrase for the part you could not write is tacit knowledge: we know more than we can tell. We recognize a face without being able to say how; we hear that a cut is late without a rule. Every skill has a tacit layer, and a skill file is made of what can be told.

The limit is not a defect of your writing. Tim Ingold argues that skill passes between people less by transmitting instructions than by educating attention: the teacher shows where to look, and the learner's perception changes through looking, many times, at real cases. A written procedure can direct attention ("compare the eyes in both shots"), and this is worth doing. But receiving the direction is not the event of becoming able to see. A student can build a rule and still not see the problem the rule is for; so can a model. What can go into the file: steps, checks, formats, where to look, what to do when something is missing, and examples, which carry more of the tacit part than descriptions do. What cannot: the judgment of what counts, the taste that ranks two acceptable results, the sense that this case is the exception.

So pair the file with a study. Build the skill, then test it and yourself on a new case: did the model's check catch what you would catch, and did you catch it? Where the file stops is a map of what you still have to practice in person.
