An interface is the surface where you meet the tool: the camera's dials, the editing timeline, the command line, the chat box. Every interface is an abstraction. It presents a few controls and a few kinds of feedback, and it hides everything else. The same model behind a chat box and behind Claude Code with a folder open is the same model. But in the chat you see a message come back; in the harness you see files change, commands run, errors appear. One interface shows you a result. The other shows you a workflow. What you can learn from the tool depends on which one you are standing at.

This is why "what do you need to know to say you know a thing" is partly a question about interfaces. An interface that exposes intermediate representations (the storyboard before the animatic, the transcript before the edit, the shot list before the shoot) gives you something to inspect, predict about, and perturb. An interface that exposes only the finished output gives you the output and your taste, and nothing between. The chat box's simplicity is not evidence that the judgment has gone away; it is evidence that the judgment has been moved out of sight. It also shapes you: a box that wants a sentence trains you to think in sentences before acting, while a canvas or a timeline lets you try first and describe afterward.

This week, notice which interface you are at for each task, and choose it. For a skill you are keeping, prefer the interface that shows the steps. For one you are delegating, at least know what the box is hiding, and the entry on [black boxes](black-box.md) names four things it might be.
